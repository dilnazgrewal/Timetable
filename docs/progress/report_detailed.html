TimeWeave

Clash-free college timetables, generated in seconds

Hackathon · Day 1 progressWednesday 21 October 2026Team: Dilnaz Grewal

Summary

On Day 1 we built a working end-to-end prototype. It generates the weekly timetable for a whole college (5 engineering departments plus Applied Sciences) using Google OR-Tools CP-SAT. A separate independent validator then proves that the result has no clashes. The app shows the result by section, teacher or room on desktop and phone. It also includes a free-room finder, teacher-load and room-usage dashboards, a read-only AI assistant, and one-page PDF printouts.

The problem

  • Teachers build the semester timetable by hand. It takes weeks and still ends up with clashes, uneven teaching loads and empty rooms.
  • Students wait for hours between lectures (for example, a class at 12:30 and the next at 3:30).
  • The timetable is fragile: one change triggers a chain of others, so problems go unfixed.
  • Nothing helps with daily changes, such as an absent teacher or a student looking for an empty room.

Our approach

  • Constraint solving, not trial and error: hard rules can never be broken, and soft goals (fewer gaps, balanced days) are optimised.
  • Trust through proof: a separate validator re-checks every timetable, and tests inject clashes to prove that it catches them.
  • Student-friendly days: the solver minimises idle gaps and gives each section a flexible lunch hour.
  • Simple for every role: a timetable office, department coordinators, teachers and students each see what they need, on a phone too.

Architecture

How a timetable is made

1 · Input
Seeded college data today. An Excel/CSV template upload comes next (Rooms, Teachers, Sections, Assignments, Settings).
▼
2 · Pre-checks
Plain-English errors before solving, e.g. "Prof. X is assigned 32 hours but can teach at most 28 with their availability."
▼
3 · CP-SAT solver
(Google OR-Tools)
Hard rules (never broken):
  • No double-booking of a teacher, a student batch or a room.
  • Teacher availability is respected (part-time and visiting staff).
  • Labs are 2-hour blocks in a lab of the right type with enough seats.
  • Flexible lunch: everyone gets a free hour between 11:30 and 2:30.
  • Daily limits apply, and a subject is taught at most once a day.
Soft goals (minimised): idle gaps between lectures, days with a single lecture, gaps in teachers' days, and 4 or more periods in a row.
▼
4 · Independent validator
Separate code with no shared logic re-checks every result: teachers, students, rooms, room type and capacity, availability, lunch, daily limits, and that every session is placed. It produces the "✔ 0 clashes" badge.
▼
5 · Saved timetable
The weekly base timetable (cached, so the app starts instantly). Date-specific overrides for absences and bookings come next.
▼
6 · Outputs
Grids by section, teacher or room · free-room finder · teacher-load and room-usage dashboards · AI assistant (read-only) · PDF printouts.

Technology

LayerChoice and reason
SolverGoogle OR-Tools CP-SAT: proves hard rules hold and optimises soft goals. Chosen over genetic algorithms, which cannot guarantee feasibility or explain failures.
BackendPython + FastAPI: a single language for the solver, the API and the AI assistant.
FrontendOne HTML page with Tailwind CSS and Alpine.js: no build step, phone-first, with print-to-PDF built in.
AI assistantClaude (Anthropic API) with read-only tools over the live timetable. It has no ability to change data.
StorageIn-memory plus a JSON cache today. SQLite comes next, then Postgres (Neon free tier) when deployed.
Qualitypytest (12 tests), git history with a commit at every milestone.

Design rules we hold to

  • The validator never shares code with the solver, so the solver never grades its own work.
  • Every future change (editor, leave request, chatbot) goes through one change engine: propose → validate → preview → apply.
  • The chatbot can only read or propose. A person always confirms.
  • Permissions are enforced on the server, not in the UI or in the AI prompt.

Planned input and output formats

Input: one Excel workbook (each sheet also accepted as CSV)
  • Settings: working days, period times, lunch window
  • Rooms: id, type, capacity, owning department
  • Teachers: name, department, type, availability
  • Sections: department, year, size, home room, G1/G2 split
  • Assignments: teacher + subject + section, theory/lab, hours/week
Outputs
  • Live web link and QR code: always current ✅ link
  • One-page PDF per section, teacher or room ✅
  • Excel export in the same format as the input Day 2
  • Calendar feed (.ics) for phones Day 3
How to run: pip install -r requirements.txt, then uvicorn app.main:app --port 8000, then open http://localhost:8000. The full plan is in PLAN.md.
